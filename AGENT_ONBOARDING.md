# Agent Onboarding

Orientation and working agreement for AI-assisted and automation-assisted
contributors to this repository. Read this before your first change.

**Order of authority.** `SECURITY.md` (vulnerability reporting) >
`CONTRIBUTING.md` (contribution governance, DCO, reviewer checklists) >
`AGENT_CONTRIBUTOR_GUIDE.md` (safe local checks, high-risk surfaces, PR
expectations) > this document (orientation + working agreement). If this
document contradicts any of them, they win — and fix this document.

This file does not replace those documents and deliberately does not repeat
them. It answers one question: *if I am asked to change X, where do I look,
what must I not break, and how do I prove it?*

---

## 1. Working Agreement

This agreement governs every change made in this repository.

1. Never commit or document sensitive information. No API keys, secrets,
   private keys, wallet material, tokens, passwords, or personal data in code,
   tests, fixtures, docs, commit messages, or logs. Adapter credentials stay in
   environment variables. Read credentials from the environment only, and never
   add an environment variable to a test in a way that makes the test depend
   on it.

2. Always commit and push code after a code change. A code change is not
   finished when the file is written; it is finished when the change is
   committed and pushed.

3. Fix defects on the spot, unless the owner decides otherwise. When a defect
   is found in the code being worked on, fix it as part of the same change
   rather than reporting it and moving on. Defer only when the owner explicitly
   decides to defer, and record the deferral.

4. Never make code changes unless they are defects. Keep the change surface
   limited to defect fixes. Do not add unrelated features, refactors, renames,
   abstractions, drive-by cleanups, or speculative improvements. Note unrelated
   observations instead of changing them.

5. Always keep corresponding documentation in sync with code changes. A code
   change updates the documents and generated artifacts that describe it, in
   the same change. This includes concept and integration docs, coding-standards
   guidance, and the generated stubs and docstrings. Maintainer-owned files such
   as RELEASES.md are updated by maintainers, not by agents.

### 1.1 How the agreement maps onto this repository

- **Secrets.** Runtime secrets live in `agent/.env` (gitignored), broker
  credentials in the OS keyring (`agent/src/trading/credentials.py`), and all
  user state under `~/.vibe-trading`. Never commit `agent/.env` files, token or OAuth
  caches, broker exports, run artifacts, uploads, memory files, or session
  databases. `python-dotenv` reads the environment for the app; tests must
  supply their own values explicitly rather than inheriting a developer's shell.
- **Commit and push.** This repository uses Conventional-Commit-style subjects
  (`fix(<scope>): …`, `feat(<scope>): …`, `test(<scope>): …`, `docs: …`). Every
  commit needs a DCO `Signed-off-by:` trailer, so commit with `git commit -s`
  after `git config user.name` / `user.email` are set to your real identity
  (`CONTRIBUTING.md`). Do not add AI-assistant attribution trailers. Confirm the
  tree is whitespace-clean with `git diff --check` before pushing.
- **Defects on the spot.** The house comment style records *why* a line exists,
  with the issue/PR number and the regression it prevents (for example
  `# Policy: strict parse ... (issue #1615)` in
  `agent/backtest/loaders/baostock_loader.py`). When you fix a defect, write
  that comment and add the targeted regression test in the same change.
- **Defect-only surface.** This repository has no feature-flag or codemod
  convention for unrelated cleanup. Unrelated findings belong in the PR body or
  an issue, not in the diff.
- **Docs in sync.** User-facing CLI/Web/MCP/connector/provider/safety changes
  update `README.md`; unreleased changes update `CHANGELOG.md`; contributor
  workflow changes update `CONTRIBUTING.md`; changes to agent rules update
  `AGENT_CONTRIBUTOR_GUIDE.md`; vulnerability-policy changes are the only edits
  to `SECURITY.md` (see the **Documentation Rules** in
  `AGENT_CONTRIBUTOR_GUIDE.md`). This repository has **no `RELEASES.md`** — its
  release-notes file is `CHANGELOG.md`, and it is maintained by the maintainers.
  The seven translated `README_*.md` files are regenerated by maintainers;
  change `README.md` and note the follow-up rather than hand-editing
  translations.

## 2. What you are working on

`Vibe-Trading` (PyPI `vibe-trading-ai`, MIT, HKUDS) is a natural-language
finance research agent that turns prompts into runnable analysis: market data →
generated strategy → backtest → reports and exports, with an Alpha Zoo, a
multi-agent swarm, a trade-journal "Shadow Account" analyzer, persistent
memory, 16 IM channel adapters, and — opt-in, user-authorized — live brokerage
trading behind a mandate / kill-switch / audit layer.

Three surfaces share one Python core:

| Surface | Entry point | Notes |
|---|---|---|
| CLI / TUI | `vibe-trading` → `cli:main` → `agent/cli/main.py` + `agent/cli/_legacy.py` | `_legacy.py` holds every non-interactive subcommand (266 KB) |
| HTTP API + web UI | `vibe-trading serve` → `agent/api_server.py` (FastAPI), SPA in `frontend/` | thin assembler: one `register_*_routes(app)` per module in `agent/src/api/` |
| MCP server | `vibe-trading-mcp` → `agent/mcp_server.py` (FastMCP) | stdio by default; `http` = Streamable HTTP at `/mcp` |

Plus two library entry points: `python -m backtest.runner <run_dir>` and
`python -m backtest.validation <run_dir>`.

**The agent loop is hand-rolled.** `agent/src/agent/loop.py` is a synchronous
ReAct loop; `langgraph` is a declared dependency but is not imported by
`agent/`. LangChain appears only behind the `ChatLLM` adapter
(`agent/src/providers/chat.py`).

## 3. The critical execution path

The server turn is the path most changes touch. Web, IM channels, and
scheduled research all funnel through it:

```text
POST /sessions/{id}/messages          agent/src/api/sessions_routes.py
  -> SessionService.send_message      agent/src/session/service.py         (one loop per session; a second is 409)
    -> _run_attempt -> _run_with_agent                                    (ThreadPoolExecutor, 4 workers)
      -> ChatLLM + build_registry + AgentLoop                             (src/tools/__init__.py:build_registry)
        -> AgentLoop.run -> _run_bound -> ContextBuilder.build_messages
          -> ChatLLM.stream_chat -> provider
            -> event_callback -> EventBus -> SSE GET /sessions/{id}/events
          -> tool calls -> ToolRegistry.execute -> GroundingLedger.ingest
        -> validate_final_answer -> release (or correct / redact) -> result
```

The CLI wraps the same loop directly (`agent/cli/_legacy.py:_run_agent`), and
every IM channel reaches the same `SessionService.send_message` through
`agent/src/channels/runtime.py`.

## 5. Setup and commands

Run these from the repository root unless noted.

| Goal | Command |
|---|---|
| Install (development) | `pip install -e ".[dev]"` |
| Reproducible install | `python -m pip install --require-hashes -r requirements-lock.txt` (channels lock: `requirements-channels-lock.txt`) |
| Interactive CLI | `vibe-trading` |
| Single run | `vibe-trading run -p "…"` (`-f`, stdin, `--json` supported) |
| API server | `vibe-trading serve` — defaults are **`127.0.0.1:8000`**; use `--port 8899` to match Docker and the docs |
| Dev servers | `vibe-trading dev` (backend 8899 + Vite 5899) or `scripts/dev up\|stop\|status\|logs` |
| MCP server | `vibe-trading-mcp` (stdio default; `--transport http` serves `/mcp` on 8900) |
| Backtest engine | `python -m backtest.runner <run_dir>` |
| Validation / Monte Carlo CLI | `python -m backtest.validation <run_dir>` |
| Python tests | `pytest --ignore=agent/tests/e2e_backtest --ignore=agent/tests/test_e2e_harness_v2.py --tb=short -q` |
| Policy gates | `bash tools/ci_grep_gates.sh` and `pytest tools/test_ci_env_var_gate.py -q` |
| Format / lint (changed files) | `black <files>` ; `ruff check <files>` |
| Frontend | `cd frontend && npm ci && npm run build` ; `npm run test:run` |

There is no database setup step: the SQLite stores under `~/.vibe-trading`
create themselves on first use.

## 7. Contracts and invariants

**Explicit — enforced by code, schema, or tests:**

- **Loader contract:** tz-naive ascending unique `DatetimeIndex` named
  `trade_date`; float `open/high/low/close/volume`; no NaT; per-frame metadata
  in `df.attrs` (`quote_currency`, `currency_conversion`, `adjustment`).
- **Alpha purity and NaN contract:** zoo modules import only the allowlist
  (`pandas`, `numpy`, `scipy.*`, `src.factors.base`, stdlib subset); operators
  propagate NaN rather than substituting zero; the registry rejects `±inf` and
  over-95%-NaN output and masks rows whose declared dependencies are missing.
- **Tool contract:** `execute(**kwargs) -> str` returning a JSON envelope;
  `status`/`ok` conventions; optional-dependency tools report
  `check_available() == False` instead of failing at call time.
- **Configuration contract:** raw `os.getenv` / `os.environ` reads are banned
  outside `agent/src/config/` (AST gate); `MARKET_DATA_ORDER_<MARKET>` must be a
  permutation of the built-in chain — a source may be reordered, never removed.
- **Run-card contract:** schema 1.0 with a `sha256` per artifact; grounding
  later requires each listed summary artifact to match the manifest
  byte-for-byte.
- **Live-trading contract:** the mandate writer is unreachable from
  agent-importable code (only `POST /mandate/commit`); clearing the kill switch
  is not an agent tool; the audit ledger is append-only and hash-chained and
  refuses to extend a broken chain; WRITE and UNKNOWN tool classes are never
  exposed ungated.
- **Prompt contract:** the system prompt and tool/skill preamble are kept
  byte-stable across runs so provider prefix caching works; volatile run state
  travels in the first user message instead.

**Implicit — strongly implied by usage:**

- One `AgentLoop` per session; never write a session from two loops.
- `agent/backtest/metrics.py` is the only place metrics are computed; auxiliary
  metrics ride `structured_metrics` rather than new top-level keys.
- A source may not silently substitute a different quote currency or adjustment
  basis for a symbol it was asked to serve.
- SSE event names are a contract with `frontend/src/hooks/useSSE.ts` and with
  channel adapters.

## 8. Safety boundaries

Get explicit owner approval before doing any of the following (from
`AGENT_CONTRIBUTOR_GUIDE.md`):

- placing, cancelling, approving, flattening, or otherwise affecting broker
  orders;
- authorizing broker, OAuth, MCP, exchange, payment, wallet, or cloud accounts;
- writing real credentials into `agent/.env`, `~/.vibe-trading/`, token caches,
  or external services;
- starting externally reachable API, MCP, SSE, webhook, or dashboard servers;
- deploying the wiki, publishing packages, triggering releases, or changing CI
  secrets;
- rewriting history, force-pushing shared branches, deleting backups, or
  removing persistent run or memory data.

Never run live trading, payment, wallet, contract, or broker-write flows as part
of routine validation.

Additional repository rules worth stating once:

- Deployments beyond loopback must set `API_AUTH_KEY`; without it the API trusts
  loopback clients only, and remote requests are refused.
- Shell-execution tools are fail-closed: they require an explicit opt-in
  (`VIBE_TRADING_ENABLE_SHELL_TOOLS` / `--enable-shell-tools`) and are excluded
  from networked entry points by default.
- Prefer sanitized fixtures over real financial data, and never copy a local
  `agent/.env`, run artifact, or private trading export into the repository.
- Generated strategy code is untrusted: it is AST-scrubbed and run in a bounded
  subprocess. Do not weaken that path.

## 9. Verification standard

A change is not verified until you have exercised the path you changed and can
say what you ran and what you did not.

- Run the **narrowest test set that covers the change**, plus the policy gates
  (`bash tools/ci_grep_gates.sh`, `pytest tools/test_ci_env_var_gate.py -q`).
- For live/order-safety changes, the minimum set is
  `test_sdk_order_gate.py`, `test_mandate_enforcement.py`,
  `test_killswitch_blocks_orders.py`, `test_readonly_default.py`.
- For factor changes, the minimum set is `agent/tests/factors/test_alpha_purity.py`
  and `agent/tests/factors/test_lookahead.py`.
- For frontend changes, `cd frontend && npm ci && npm run build` must pass.
- State explicitly in the PR what was **not** run. Skipped is not tested.
- Do not claim a result you did not observe. If a dependency is missing in your
  environment, say so instead of reporting the suite green.

Test isolation is load-bearing: `agent/tests/conftest.py` redirects the runtime
root to a temporary directory at import time and fails the run if anything
writes the developer's real `live/audit*.jsonl`. Do not export
`VIBE_TRADING_HOME` while running tests, and do not add tests that depend on an
environment variable being present.

## 10. Writing style in this repository

- `from __future__ import annotations` in every module; PEP 604 unions; type
  annotations on all public functions.
- Frozen `@dataclass` for value objects and domain models; Pydantic only at
  configuration and tool-argument boundaries.
- Module docstring states the module's responsibilities. Public functions carry
  Args / Returns / Raises.
- Comments explain **why**, with the issue, PR, or date that motivated the line,
  and the regression it prevents. This is the strongest convention here —
  imitate it.
- Internal failures raise named exception types; tool and API boundaries return
  structured envelopes (`{"status": ...}` / `{"ok": ...}`) instead of leaking
  tracebacks.
- Configuration is read through `EnvConfig` and the file-config loader, never
  from `os.environ` directly.
- The agent loop and tools are synchronous; `asyncio` belongs to the HTTP, SSE,
  and scheduler layers.

## 12. When blocked

- Missing credentials, an unreachable broker, or an approval you do not have are
  **owner decisions**, not defects to route around. Record the deferral
  explicitly (what was deferred, why, and where it will be picked up) and stop
  rather than weakening a safety gate.
- If a needed dependency or extra is absent, say which extra is missing
  (`pip install "vibe-trading-ai[<extra>]"`) instead of silently degrading a
  test or a code path.
- If the working agreement and a repository gate appear to conflict, the gate
  wins for safety-relevant changes and the conflict is raised with the owner.
